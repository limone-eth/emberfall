# Which stack for the permadeath 2D MMO?

Decided: 2026-10-31 · Case: c_f2cfee48-17f0-4d26-b6d7-294c84435081

## Question and choice
Which stack do we use for an online, permadeath, top-down 2D bullet-hell MMO (same genre as Realm of the Mad God, with its own name, classes, art and world)?

Choice: "TypeScript monorepo: PixiJS client, Node + ws authoritative server at 20 Hz, shared game code, FastNoiseLite world gen, SQLite".

## Why
- The hard part of this genre is netcode for many bullets. A custom server gives full control of bandwidth.
- One language for client, server and shared rules.
- Runs in any browser with no install.
- Most of the 10 libraries the human shared (Jolt, ozz-animation, Recast, Terrain3D, godot_voxel, Material Maker, The Forge, meshoptimizer) are 3D C++ tools and do not fit. FastNoise (as FastNoiseLite) fits for world gen. Effekseer (WebGL runtime) can come later for VFX.

## Constraints
- The server is authoritative: it owns hits, damage, loot, XP and death.
- Bullets are deterministic from a volley event (seed, origin, angle, time). The server sends volleys, not bullets.
- Server tick is 20 Hz. The client renders at display rate with interpolation.
- Death deletes the character. The account keeps a vault and a graveyard entry.
- All names, classes, art and content are original.

## Ruled out
- Phaser 3 + Colyseus: per-bullet state sync costs too much bandwidth, less control at scale.
- Godot 4 web export: large, slow web export, and the server is still a custom build.
